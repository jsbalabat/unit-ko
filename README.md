# UnitKo

Rental property management for landlords. Track properties, units and bed spaces, tenant records, recurring billing cycles, and payments, with per-landlord data isolation enforced at the database level.

**Live:** [unitko.vercel.app](https://unitko.vercel.app)

---

## Stack

| Layer | Technology |
|---|---|
| Web | Next.js 16, React 19, TypeScript |
| API | TypeScript service layer over Supabase |
| Database | PostgreSQL via Supabase, with row-level security |
| Monorepo | Turborepo 2.3 on pnpm 9 workspaces |
| Runtime | Node 22+ |
| Containers | Docker Compose |

## Repository layout

```
apps/
  web/        Next.js frontend
  api/        API layer
packages/
  db/         Schema, migrations, RLS policies, typed database client
  shared/     Types and utilities shared across apps
```

Turborepo orchestrates builds and caching across the workspace; `packages/shared` is the single source of truth for cross-app types.

## Database

Most of the engineering in this project lives in `packages/db`. The schema is versioned as plain SQL rather than generated by an ORM, which keeps row-level security policies and atomic operations explicit and reviewable.

It covers:

- **Normalized schema** for properties, units, bed spaces, tenants, leases, billing entries and payments, with the denormalized columns from the original build dropped in a dedicated migration.
- **Row-level security policies** scoping every table to the owning landlord, including a consolidation pass that removed redundant and overlapping policies.
- **Atomic RPC functions** for multi-table operations that must not partially apply, such as property creation, property updates, and the archive-and-reset flow.
- **Activity logging** with a supporting index for tenant-scoped queries.

## Getting started

Requires Node 22+ and pnpm 9.

```bash
pnpm install
cp .env.docker.example .env    # then fill in your Supabase credentials
pnpm dev
```

### Workspace scripts

| Command | Description |
|---|---|
| `pnpm dev` | Run all apps in development |
| `pnpm build` | Build all packages and apps |
| `pnpm lint` | Lint the workspace |
| `pnpm test` | Run the test suites |
| `pnpm typecheck` | Type-check the workspace |

Each runs through Turborepo, so results are cached and only changed packages rebuild.

### Docker

```bash
docker compose up
```

## Status

Actively developed. The current work is a migration from the original Next.js and Supabase monolith to this Turborepo structure, alongside a normalization pass on the schema. Legacy migrations are retained under `packages/db/legacy-migrations` for history.
